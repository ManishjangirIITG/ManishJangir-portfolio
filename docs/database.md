# Database

The portfolio uses PostgreSQL as the source of truth and Drizzle ORM for schema management and migrations.

## Principles

- PostgreSQL is the source of truth for editable portfolio content and private admin sessions.
- Drizzle owns the application schema and migration workflow.
- Content is normalized into relational tables rather than stored as a large JSON document.
- UUID primary keys are generated by PostgreSQL.
- Public content can be filtered by `published` status.
- Authentication data is isolated from public content tables.

## Content model

- `projects`: project-level metadata and publishing state.
- `project_sections`: ordered case-study sections belonging to a project.
- `technologies`: canonical technology records.
- `project_technologies`: many-to-many project/technology relationship.
- `experiences`: professional/academic experience records and ordering.
- `updates`: publishable portfolio updates.

## Authentication model

- `admin_users`: authorized administrator identity, password hash, active state, and login timestamp.
- `admin_sessions`: hashed opaque session tokens with expiry and usage timestamps.

The raw session token is stored only in the HTTP-only browser cookie. The database stores its SHA-256 hash.

## Local setup

Set `DATABASE_URL` in `.env.local`, then run:

```bash
npm run db:migrate
```

To create a new migration after changing `src/db/schema.ts`:

```bash
npm run db:generate
```

Review generated SQL before applying it.

## Migration history

- `0000_initial_content_model`: Phase 2 content foundation.
- `0001_admin_auth`: Phase 3 administrator and session tables.

## Phase boundary

Phase 3 does not add content CRUD, revisions, audit trails, analytics, media metadata, or production database hosting configuration. Those remain separate concerns for later phases.
