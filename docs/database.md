# Database

Phase 2 introduces the PostgreSQL persistence layer using Drizzle ORM.

## Principles

- PostgreSQL is the source of truth for editable portfolio content.
- Drizzle owns the application schema and migration workflow.
- Content is normalized into relational tables rather than stored as a large JSON document.
- UUID primary keys are generated by PostgreSQL.
- Public content can be filtered by `published` status without requiring the admin system.
- Revisions, audit records, authentication, media metadata, and analytics are intentionally deferred to their later phases.

## Content model

- `projects`: project-level metadata and publishing state.
- `project_sections`: ordered case-study sections belonging to a project.
- `technologies`: canonical technology records.
- `project_technologies`: many-to-many project/technology relationship.
- `experiences`: professional/academic experience records and ordering.
- `updates`: publishable portfolio updates.

## Local setup

Set `DATABASE_URL` in `.env.local`, then run:

```bash
npm run db:migrate
```

To create a new migration after changing `src/db/schema.ts`:

```bash
npm run db:generate
```

Review generated SQL before applying it.

## Phase boundary

This phase does not add admin authentication, CRUD screens, revisions, audit trails, seed content, analytics, or production database hosting configuration. Those are separate concerns and will be introduced in later phases.
