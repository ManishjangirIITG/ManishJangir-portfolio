# Development Notes

Phase 1 is the foundation only. Do not add production dependencies for Phase 2+ concerns yet.

## Dependency policy

Before introducing a dependency, document:

1. The problem it solves.
2. Why the existing platform cannot solve it adequately.
3. Its operational and maintenance cost.
4. How it will be tested.

## Phase boundaries

- Phase 1: application foundation
- Phase 2: database/content model
- Phase 3: authentication/CMS
- Phase 4: public portfolio content
- Phase 5: system inspection/telemetry
- Phase 6: analytics
- Phase 7: testing/benchmarks
- Phase 8: CI/CD/deployment
- Phase 9: hardening
